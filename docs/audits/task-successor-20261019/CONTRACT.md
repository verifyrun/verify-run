# Declared task succession, first version

This additive reader verifies a bounded genesis-to-head chain of original service test observations. It does not rewrite existing previews or assign predecessor relations to legacy packets. Missing binding is UNESTABLISHED and refuses this reader.

The producer must put `vfy.service-test-task-binding/1` in the preview **before** original signed admission. It contains the exact task digest, consecutive revision, exact previous verified observation digest, and false authority/retry flags. Existing original signed accounting binds the preview. Every link is rechecked by the original `TestObservationChecker` using host-selected checker/trust objects. Uploaded records cannot select those objects. The task bytes/digest and destination head must be independently selected by the host.

The chain preserves exact requirements, examiner, environment, adapter, capture, runner, labels, cases and requirement mapping. Source identity may change. The predecessor hash binds the full original verified observation including selected archived accounting snapshot and verifier limits; changing that selection is not equivalent continuation. The final destination predecessor must equal the verified penultimate observation (None for genesis). Destination equality is not an atomic insertion: the authenticated destination transaction is a remaining implementation gate.

Limits: 64 links, 128 KiB task, 16 MiB aggregate selected/raw evidence; original per-observation limits remain. This is not a hard CPU/memory isolation claim. Exact-class checker objects are trusted host inputs, not an upload or callback API.

Result: authenticated *declared* task sequence. Semantic adequacy, repair causality, current source and authority are not established. This verifier neither launches commands nor signs, retains, consumes or retries an operation.
