# One selected development CHECK

`execute-selected-check --profile ABS --profile-sha256 SHA --request-sha256 SHA --authorization-monotonic-ns NS` consumes an exact M01 proposal on stdin. The operator-owned profile is `vfy.check-execution-profile/1` with accounting_profile/accounting_profile_sha256, proposal_sha256, platform_context_sha256 engineer_package {root,files}, and launch_window_seconds (1..30). The complete selected installed Engineer Python file population is pinned, linked/extra executable members refused. The host must select this profile independently of uploader input and revalidate current task/caller/approval under its authority lock and durably commit a single invocation. It captures a same-host monotonic timestamp before that transaction, passes it only after the known original successful commit, and refuses cached/retried invocation. Post-commit revocation is not retroactive; no atomic cross-store or current-at-child-launch assertion is made. The context digest is a selected reference, not remote authentication. Run rejects future/expired stamps before admission, consumption and the guarded immediate-before-launch hook. Timestamp/deadline outputs are decimal strings (nanoseconds can exceed JSON safe integers). The final check is not an OS-atomic clock/exec primitive; trusted host scheduling and clock remain assumptions.

The existing allocator fence is held throughout exact-head validation, admission, guarded Engineer execution, one-use consumption and settlement. The existing executor rechecks captured source, examiner, environment, sandbox policy, task, selected runner and preview. No serialized admission ticket is a reusable capability. Any interrupted or rejected admitted attempt retains its hold and is not retried. The command performs a bounded check only, never application adoption.

`status-selected-check` takes the same profile/request arguments and exact proposal stdin, authenticates current retained accounting with selected trust, and identifies the exact request entry. ABSENT_NOT_RETRY_PERMISSION is not permission to launch. Pending publication refuses status; callers must retain UNKNOWN rather than assume absence. Host process death can leave ADMITTED or CONSUMED; no capability is reconstructed.

Trust limits: this is an operator-controlled local development host with a trusted supplier directory and no concurrent supplier writer, existing macOS sandbox executor, system Python/native/OS trust. Runtime package correspondence is not loaded-byte attestation. Source capture exclusions and selected-case semantics are unchanged. The Platform caller/current-task gate is separately enforced at its durable one-shot commit under its authority lock; a caller-supplied context alone confers nothing. Native sandbox execution and real Platform integration require separate installed evidence from source controls.
