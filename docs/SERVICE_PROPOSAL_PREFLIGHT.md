# Selected proposal preflight

`vfy preflight-service-proposal --request-sha256 SHA` reads one bounded JSON request from stdin. It verifies separately selected signed accounting/trust, exact request and approval, selected requirements/cases/runner, preview byte correspondence and declared task binding. It does not inspect live pool files, reserve capacity, admit or execute anything.

Request schema: `vfy.service-proposal-preflight-request/1`; fields are schema, module_sha256 (existing pinned selected-case checker), minimum_revision, limits and inputs. Inputs are digest-pinned base64 context, snapshot, selection, requirements, runner, preview, request, approval, workflow, task and platform_context. Context follows the existing selected-case reader's independent trust/config/policy selection. Limits follow that reader's bounded input/output/case/requirement contract. The platform context is opaque selected bytes, not authenticated organizational authority.

A matching attempt/root/preview already present in the supplied signed snapshot is refused. Absence from that snapshot does not prove live freshness or available capacity. Success means SELECTED_PROPOSAL_BYTES_VERIFIED only. Workflow checks cover selected schema/scope/labels/observation ceilings, not full workflow admission or runtime provenance. Actual runtime identity, full semantic coverage and current source remain independent obligations. Live admission must recheck the current pool/head and exact preview/request/approval. Old approvals never transfer to a recaptured root.

This additive module does not modify the pinned service_tests reader. The six focused synthetic controls test signed approval mismatch, byte pins, source/task/selection changes, prior admission, read-only behavior and bounds. Synthetic fixture setup is not real source execution or fresh customer admission.
